## 1. Реактивная модель и Observable

**Reactive Extensions for JavaScript (RxJS)** — это реализация паттерна «наблюдатель» (Observer) с поддержкой функциональной композиции. Она вводит понятие **Observable** — ленивого источника множественных значений, доставляемых асинхронно во времени.

Важнейшее отличие от привычных pull‑систем (массивы, итераторы) состоит в том, что потребитель не запрашивает данные, а подписывается на поток и **реагирует** на события по мере их появления.

Angular выбрал RxJS в качестве стандартного механизма для работы с асинхронными операциями: HTTP‑запросы (`HttpClient`), события маршрутизатора (`Router`), изменения реактивных форм (`FormControl.valueChanges`) — всё это основано на Observables. Такой подход обеспечивает единообразное управление временем, отменой и композицией операций.

## 2. Сравнение с Promise

Promise описывает **однократное** отложенное значение и исполняется немедленно (eager). Observable, напротив:

- может эмитировать **ноль, одно или множество** значений;
- является **ленивым** — выполнение начинается только после вызова `subscribe()`;
- поддерживает **отмену** через `unsubscribe()` или операторы завершения;
- предоставляет богатый набор операторов для трансформации, фильтрации и координации нескольких потоков.

Пример сопоставления двух парадигм:

| Критерий                | Promise                          | Observable                                               |
| ----------------------- | -------------------------------- | -------------------------------------------------------- |
| Количество значений     | Одно (или ошибка)                | Множество (потенциально бесконечное)                     |
| Старт выполнения        | Немедленный                      | При подписке                                             |
| Отмена                  | Через `AbortController` (внешний)| Встроенная (`unsubscribe`, `takeUntil`, `takeUntilDestroyed`) |
| Операторы трансформации | `.then()`, `.catch()`            | `pipe()` и более 100 операторов                          |
| Завершение              | Автоматически                    | Явный `complete()` или `error()`                         |

Используйте Promise там, где нужен однократный результат (например, загрузка конфигурации при старте приложения). Во всех остальных сценариях асинхронного взаимодействия, типичных для UI, применяйте Observable.

## 3. Жизненный цикл Observable

Любой Observable проходит следующие этапы:

1. **Создание** (creation) — объявление логики потока с помощью конструктора `new Observable()` или операторов создания (`of`, `from`, `fromEvent` и т. д.). На этом этапе поток остаётся холодным.
2. **Подписка** (subscription) — вызов `subscribe()` запускает исполнение. Каждый подписчик получает собственное независимое исполнение, если не применены операторы мультиплексирования.
3. **Исполнение** (execution) — генерация уведомлений: `next(value)`, `error(err)` или `complete()`.
4. **Удаление** (teardown) — при вызове `complete()` или `error()`, либо при ручном `unsubscribe()`, срабатывает функция‑освободитель, возвращённая из конструктора. Здесь освобождаются ресурсы (удаляются обработчики событий, закрываются WebSocket‑соединения).
